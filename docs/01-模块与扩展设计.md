# 模块与扩展设计 · v1.0

> 目标：核心规则先跑通，内容全部数据驱动，后续加事件/职业/技能/剧本不改核心代码。

## 1. 总体架构

```
[客户端 Screen/HUD/特效]
        │ C2S 请求 / 选择 / KP动作
        ▼
[网络层 SimpleChannel] ──► [服务端 KP/命令处理器]
        ▲                        │
        │ S2C 同步/结果/事件      ▼
[ClientCache] ◄──────── [Rules 核心 + CharacterSheet]
                                 │
                                 ▼
                        [CocWorldData SavedData]
                                 │
                                 ▼
                     [EventRegistry / ScenarioRegistry]
                        （内置 JSON + config/coc/*.json）
```

- 服务端是唯一权威：属性、技能、SAN、事件结果、随机、存档。
- 客户端只做展示、输入、动画和本地视觉特效。
- 单人游戏：内置服务端与客户端同进程，仍然走同一套网络包逻辑，保证多人一致。

## 2. 模块明细

### M1 core
- `CallOfCthulhu`：`@Mod` 入口；注册网络、命令、事件监听、客户端初始化（反射隔离）。
- `CocServerConfig`：`config/coc-server.json` 读写（随机事件开关/间隔/KP名单/事件超时等）。
- 扩展点：新增服务端配置字段只需改 DTO + 默认值；新增生命周期监听只需加方法。

### M2 rules（纯逻辑，不依赖 UI）
- `DiceRoller`：骰子表达式解析与投掷（NdM±K，N≤100，M∈{2,3,4,6,8,10,12,20,100}）；d100 百分骰（十位/个位，00+0=100）；奖励/惩罚骰（最多 2）；成功等级判定；大成功/大失败。
- `SkillRegistry`：技能定义（id、中文名、基础值公式、是否可成长）。新增技能=加一行定义。
- `OccupationRegistry`：职业（id、中文名、点数公式、职业技能列表、描述）。新增职业=加一条定义。
- `CharacterRules`：属性生成（3d6×5、2d6+6×5、3d6+3×5）、年龄修正、衍生值（HP/MP/SAN/MOV/DB/体格）、技能基础值计算、创建校验。
- `SanityRules`：SAN 损失、单次≥5 临时疯狂、单日≥1/5 不定期疯狂、疯狂表（1d10）、恐惧症/狂躁症表、最大 SAN=99-神话、SAN=0 永久疯狂。
- `ImprovementRules`：成长检定（d100>技能则 +1d10，上限 99）。
- `CheckService`：技能/属性检定、孤注一掷、花费幸运、对抗检定；维护"最后一次检定"（仅服务端内存，5 分钟有效）。
- 扩展点：新增成功等级/新规则只改本模块；UI 只消费结果 DTO。

### M3 character
- `CharacterSheet`：玩家角色卡。字段：
  - 身份：uuid、name、age、occupationId、occupationName
  - 属性：STR/CON/SIZ/DEX/APP/INT/POW/EDU/LUCK
  - 衍生：hp/maxHp、mp/maxMp、san/maxSan、mythos、mov、db、build
  - 技能：Map<skillId, value>
  - 成长：Set<skillId> improvementMarks
  - 疯狂：tempInsanityEndGameTime、tempInsanityName、indefiniteInsanity、phobias、manias、retired
  - 记录：dailySanLoss、lastSanDay、handouts（线索）、backstory（背景条目）、notes
- NBT 序列化/反序列化；所有读写做空值保护。
- 扩展点：新字段加 NBT key + 默认值；旧存档缺字段自动补默认。

### M4 persistence
- `CocWorldData extends SavedData`：
  - `Map<UUID, CharacterSheet> sheets`
  - `Map<UUID, Long> lastRandomEvent`
  - `Map<String, Long> eventCooldowns`
  - `Set<String> firedOnce`
  - `ScenarioState scenario`
- 存在主世界 `getDataStorage()`，键 `coc_world_data`。
- 扩展点：新世界级状态加字段 + save/load；不做玩家 Capability，避免注册复杂度。

### M5 events
- DTO：`EventDef`、`EventConditions`、`EventOption`、`EventOutcome`、`EffectDef`、`ScenarioDef`。
- `EventRegistry`：
  - 内置：jar 内 `assets/coc/events/index.json` + 各事件 JSON。
  - 自定义：`config/coc/events/*.json`，同 id 覆盖内置。
  - 剧本：`config/coc/scenarios/*.json` + 内置 `assets/coc/scenarios/`。
  - `/coc reload` 重载；解析失败只记录并跳过，不崩服。
- `EventScheduler`：每 20 tick 检查；按配置间隔选在线玩家；按权重/条件/冷却挑选；发事件卡。
- `EventResolver`：选项→技能检定→成功/失败结果→效果列表→线索/连锁事件→记录冷却/一次性。
- `EffectApplier`：效果类型注册式 switch：
  - `san/hp/mp/luck/skill/mythos`（数值支持表达式，如 `-1d6`）
  - `item/effect/sound/message/handout/broadcast/spawn`
  - 以后加 `type` 分支即可；事件 JSON 不执行任意命令。
- `ScenarioManager`：开始（发 intro 线索）→ 下一幕（对所有有角色卡玩家发事件）→ 结束（outro + SAN 奖励）。
- 扩展点：事件/剧本 100% JSON；新效果类型加一个分支 + 文档。

### M6 kp
- `KpManager`：判定 KP：
  1. 单人主机 UUID；
  2. OP 权限等级 ≥2；
  3. `config/coc-server.json` 的 `kpNames` 名单。
- `KpActions`：统一服务端动作处理（供命令与面板复用）：
  - 查看/设置 SAN、HP、MP、幸运、神话、技能
  - SAN 检定、成长检定、清除疯狂
  - 触发事件、随机事件、开始/推进/结束剧本
  - 发放线索、广播、重载数据、修改随机事件设置
- `CocCommands`：Brigadier 命令树；玩家命令权限 0，KP 命令走 `KpManager`。
- 扩展点：新 KP 动作在 `KpActions` 加 action 字符串分支，面板加按钮即可。

### M7 network
- `CocNetwork`：SimpleChannel `coc:main`，协议版本 `1`。
- 包：
  - C2S：RequestSync、CreateCharacter、Roll、CheckAction（push/luck）、EventChoice、KpAction、OpenScreenRequest
  - S2C：SyncSheet、RollResult、EventOffer、EventResult、KpData、Handout、OpenScreen、Toast
- 复杂数据统一 NBT；小数据用 `writeUtf/int/bool/uuid`。
- 全部 handler `enqueueWork` 回主线程；客户端包 `DistExecutor` 隔离。
- 扩展点：新包 = 新类 + 注册一行 + 文档。

### M8 client-ui
- `ClientSetup`：按键注册、客户端事件注册、配置加载。
- 按键：`C` 角色卡、`R` 掷骰、`K` KP 面板、`J` 线索日志。
- 界面：
  - `CharacterCreationScreen`：属性/职业页 + 技能分配页。
  - `CharacterSheetScreen`：角色卡展示（技能滚动列表、状态、SAN 条），KP 可查看他人。
  - `DiceScreen`：骰子表达式、技能检定、难度、奖惩骰、结果、孤注一掷、花费幸运。
  - `EventScreen`：事件叙事 + 选项 + 结果。
  - `KpScreen`：玩家/事件/剧本/工具四页签。
  - `SettingsScreen`：低 SAN 特效总开关、扭曲强度、镜头晃动、暗角、低语、HUD、骰子浮层。
  - `JournalScreen`：线索日志。
- 暂停菜单增加"克苏鲁设置"按钮；设置也可从角色卡进入。
- 扩展点：新页签=加一个 tab 枚举 + 渲染分支；新界面=新 Screen + 按键/命令打开。

### M9 client-fx
- `SanityEffects`：
  - 低 SAN：去饱和后处理（自建 `coc:shaders/post/low_san.json`，复用原版 `color_convolve`/`blit` 程序）。
  - 疯狂/极低 SAN：扭曲+色相流动（自建 `coc:shaders/post/insane.json`，复用原版 `wobble`/`color_convolve`/`blit` 程序；`Time` 由原版 PostPass 自动更新）。
  - 镜头晃动：`ViewportEvent.ComputeCameraAngles`，强度随 SAN 比例和设置。
  - 边缘暗角：`RenderGuiEvent.Post` 程序化绘制，不依赖贴图。
  - 低语/心跳：ActionBar 文本 + 原版环境音；间隔随机。
  - 状态机：记录自己加载的 `PostChain`；只关闭自己的效果，避免误关其它模组/原版效果。
- `SanityHud`：SAN/HP/MP/幸运条、疯狂状态、成长提示。
- `RollOverlay`：检定结果浮层（骰子数字滚动动画 + 成功等级）。
- 扩展点：新特效层加一个方法/开关；设置项加字段。

### M10 docs/build
- `build_manual.py`：离线编译 + 资源展开 + 打包 + RAT 重映射。
- 文档 `00`~`05`。
- 发布：jar 复制到 `mods\`，可选源码 zip 到 `开发文档\`。

## 3. 数据流

### 3.1 创建角色
1. 客户端随机属性（含年龄修正）→ 选职业 → 分配职业技能点/兴趣点。
2. C2S `CreateCharacter`（NBT：属性、职业、技能、背景）。
3. 服务端校验并建立 `CharacterSheet`：SAN=POW、HP/MP 派生、maxSan=99、记录成长标记为空。
4. 保存 SavedData → S2C `SyncSheet` → 客户端关闭创建界面。

### 3.2 技能检定
1. 客户端/命令发起 → C2S `Roll`（技能 id、难度、奖惩骰）。
2. 服务端读角色卡 → 掷 d100 → 成功等级 → 记录 lastCheck（可孤注一掷/花幸运）。
3. S2C `RollResult` → 浮层动画 + 聊天记录；成功技能自动打成长标记。

### 3.3 事件
1. 调度器/KP 选事件 → 服务端校验条件 → 生成 `PendingOffer`（2 分钟超时）。
2. S2C `EventOffer` → 客户端弹出事件卡。
3. 玩家选选项 → C2S `EventChoice` → 服务端检定/应用效果 → S2C `EventResult`。
4. 线索写角色卡；SAN 损失走 `SanityRules`；可能触发疯狂/连锁事件。
5. 超时自动按第一个选项结算并提示。

### 3.4 低 SAN 特效
服务端 SAN/疯狂状态 → S2C `SyncSheet` → 客户端每 tick 计算比例 → 选择后处理/晃动/暗角/低语 → 设置关闭时立即卸载自己的后处理。

## 4. 版本路线

- **v1.0（本次）**：上述全部核心 + 20+ 随机事件 + 1 个示例剧本 + 完整 UI/特效/命令。
- **v1.1**：更多事件包、更多职业/技能专精、NPC 对抗面板、物品线索（书/照片）。
- **v1.2**：战役存档（多剧本进度）、KP 事件编辑器 GUI、导入导出角色卡 JSON。
- **v2.0**：服务端独立跑团模式（无 Minecraft 世界探索，纯场景/对话），可选语音/文字团辅助。

## 5. 明确不做（v1.0）

- 不执行事件 JSON 里的任意命令（安全）。
- 不修改原版战斗伤害公式；COC 战斗仅提供对抗/伤害加成辅助，实际战斗仍由 MC 进行。
- 不引入第三方模组依赖（含 Fabric 的 Sanity 模组）。
- 不复制原版 shader 源码；只复用原版已注册的 shader 程序，自建 post JSON 调参。

## 12. v2.0.0 KP 主导架构

- `C2SKpRoll`：KP 代掷/公开掷；字段 target/kind/skillId/difficulty/bonus/expression。

- `S2CItemList`：选中玩家背包（slot/id/name/count）。
- `S2CBookData`：剧情之书（主线 acts + 支线 sides + options）。
- 协议版本升到 `2`；新增包必须升版本。

### 12.2 服务端
- `CheckService.rollForKeeper` + `broadcastPublic`：只允许 KP，结果广播给所有在线玩家。
- `ScenarioManager`：不再调用 `CocEventService`；start/next/act/end 只发幕布。
- `ItemService`：背包列表、发放、取走 1 件并公开 d100 使用检定。
- `BookDataBuilder`：从 `ScenarioDef` + `EventDef` 生成主线/支线全文；支线触发读 `EventDef.triggerHint`。
- `KpActions`：新增 `book/items/item_give/item_use/hp_set/mp_set/luck_set`；旧事件动作不再有 UI 入口。
- `CocServerEvents`：停止随机事件 tick。

### 12.3 客户端
- `KeeperScreen`：玩家/掷骰/道具/剧情书/工具五页，替代旧 `KpScreen`。
- `CurtainScreen`：无选项幕布。
- `StoryBookScreen`：主线/支线两页签，左章节目录 + 右可滚动详情；主线“向玩家显示此幕”。
- `ItemPickerScreen`：常见中文道具 + 自定义 ID + 数量。
- `AdjustPlayerScreen`：SAN/HP/MP/幸运设置，HP/MP/幸运 ±5。
- `BackstoryScreen`：角色卡底部“背景”入口，小窗口可滚动。

### 12.4 扩展点
- 新剧本：只加 `scenarios/*.json` + 事件 JSON；剧情书自动读取。
- 新支线：挂到 `acts[].sideEvents` 并写 `triggerHint`；剧情书支线页自动出现。
- 新道具：`ItemPickerScreen.COMMON` 加一行 ID/中文名；服务端校验注册表。
- 新 KP 工具：`KpActions` 加 action + `KeeperScreen` 加按钮；不要改网络包字段。
- 新幕布字段：扩展 `S2CActCurtain` NBT 与 `CurtainView`，保留旧字段兼容。

## 13. v2.0.0 玩家剧本导入

### 13.1 数据流
- 玩家在 `ImportScenarioScreen` 用系统文件选择器读取 JSON → `C2SImportScenario` → 服务端 `ScenarioImportService`。
- 服务端用 Gson 解析简化 DTO `Package/Act/Side/Option`，严格校验后生成标准 `ScenarioDef` + `EventDef`。
- 写入 `config/coc/scenarios/<id>.json` 与 `config/coc/events/import_<id>_*.json`，再 `EventRegistry.reload()`。
- 成功后广播；对在线 KP 逐个 `KpDataBuilder.send`，剧情书列表即时更新。

### 13.2 导入格式（`coc-scenario-v1`）
- 顶层：`format/id/title/description/intro/outro/sanReward/acts`。
- 幕：`title/summary/trigger/description/options/sideEvents`。
- 选项：`text/skill/difficulty/success/failure/outcome`（纯文本，无 effects）。
- 支线：`title/trigger/description/options`。
- 限制：64KB、24 幕、8 选项、8 支线；id `^[a-z][a-z0-9_]{2,31}$`。

### 13.3 安全边界
- 不接受 effects/item/spawn/command；不执行任意服务端动作。
- 生成事件只作为剧情书内容；不自动弹事件卡。
- 固定写入 `config/coc` 子目录；不覆盖内置/已存在 id。
- 失败清理临时与已写文件；成功/失败都通过 `S2CImportResult` 返回。

### 13.4 扩展点
- 新字段：在 `ScenarioImportService.Package/Act/Side/Option` 增加字段并校验，转换到 `EventDef`。
- 新校验：`validate` + `validateOptions`；生成事件必须至少有 1 个 option（无则生成“KP 自行模拟”占位）。
- 新 UI 入口：玩家 `J → 导入剧本`；KP `K → 剧情书 → 导入剧本`。

## 14. v2.0.0 剧情书线索与 KP 道具规则

### 14.1 线索标注
- `EventDef.Outcome.handout` 作为线索文本；`BookDataBuilder` 输出 `success_clue/failure_clue/clue`。
- `BookView.Option` 与 `StoryBookScreen` 显示“成功线索/失败线索/线索”；无则“无线索”。
- 导入格式支持 `clue/successClue/failureClue`，只写文本；不自动发给玩家。

### 14.2 道具库与规则
- `ItemLibrary`：`config/coc/items.json` 持久化 `id/skill/target`；服务端校验物品/技能，目标 1~100。
- `KpDataBuilder` 下发 `item_rules`；`KpView` 解析；`ItemPickerScreen` 显示 `★ 已配置`、技能/目标。
- `ItemRuleScreen`：技能 ID（可空）+ 目标点数；保存走 `C2SKpAction("item_rule", text=id|skill, value=target)`。
- `ItemService.use`：服务端优先使用道具规则；无规则才使用页面临时目标。避免客户端伪造目标。
- 扩展点：新道具 ID 直接配置；新技能写 `SkillRegistry`；规则文件可手动编辑。

## 15. v2.0.0 中英双语（同一 jar）

### 15.1 语言选择
- 不新增模组开关；直接跟随 Minecraft 客户端语言：`en_us`/`en_gb` 等 `en*` 显示英文，其它显示中文。
- `CocLang.english()` 读取 `LanguageManager.getSelected()`。

### 15.2 文本层
- `assets/coc/lang/coc_en.json`：中文原文 → 英文翻译（1547 条，含 UI、服务端消息、技能/职业、剧情文本、理智表）。
- `CocLang.tr(String)`：客户端 UI/剧情精确翻译；`CocLang.message(String)`：聊天消息先精确、再长短语替换。
- 客户端屏幕字符串统一包 `CocLang.tr`；`CocUi.title/wrapped/styleWidgets` 再做一次兜底。
- 剧情书/幕布/KP 剧本列表在显示字段时调用 `CocLang.tr`，所以服务端仍只发中文原文。
- 技能/职业/状态/恐惧症/狂躁症/低语/HUD/检定浮层全部通过同一字典翻译。

### 15.3 服务端消息
- 服务端仍发送中文 `Component.literal`；客户端在 `ClientChatReceivedEvent.System` 中做精确/短语翻译，不改变服务端逻辑。
- 自定义玩家名、物品名、非内置长文本可能保持原文。

### 15.4 扩展点
- 新 UI 字符串：加入 `coc_en.json` 并在显示处调用 `CocLang.tr`。
- 新剧情文本：翻译后加入同一字典（中文原文为 key）。
- 新语言：复制 `coc_en.json` 为对应语言文件，并在 `CocLang` 增加语言前缀映射。

## 3. v2.0 / v2.1 模块增量

> 上文的 v1.0 架构保留；以下是 KP 主导改版与 v2.1 的增量，阅读代码时以本节为准。

### 网络
- `CocNetwork` 协议版本已升到 `4`；新增包：
  - `C2SGlobalSettings` / `S2CGlobalSettings`
  - `C2SExportSheet` / `S2CSheetJson`
  - `C2SImportSheet` / `S2CSheetResult`
  - `C2SItemRule`
  - v2.0 的 `C2S`/`S2C` 幕布、剧情书、公开掷骰、KP 数据包继续保留。
- 新增/删除包必须同步升协议；客户端与服务器必须同一 jar。

### 服务端
- `GlobalSettingsService`：保存/广播角色创建点数规则，写入 `CocServerConfig`。

### 数据

- `config/coc/items.json` 的条目新增 `name`，旧文件缺省为空，兼容。
