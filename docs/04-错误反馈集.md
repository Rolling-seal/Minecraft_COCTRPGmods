# 错误反馈集

> 规则 4：收到反馈先回溯 `03-完成记录.md`，再在此新增条目。
> 每条必须包含：现象、根因、修复、防复发检查项、状态。
> 状态：待验证 / 已修复 / 已规避 / 环境问题。

## 初始风险条目（来自环境勘察与上一项目教训）

### E01 中文路径导致 javac 参数文件/编码问题
- **现象（预判）**：源码放在含"克苏鲁的呼唤"的路径下，javac 的 `@argfile` 或 classpath 在 Windows 默认 GBK 下解析失败。
- **根因**：Java 17 的 javac argfile 使用平台默认编码；中文路径 + UTF-8 源文件混用易出错。
- **修复**：源码工程放 ASCII 路径（workspace `coc-mod`），编译后只把 jar/文档复制到中文工作目录。
- **防复发**：构建脚本中所有源码/输出/依赖路径必须为 ASCII；中文只出现在源文件内容和 JSON 中。
- **状态**：已规避（构建脚本按此设计）。

### E02 官方名 -> SRG 重映射遗漏导致运行时 NoSuchMethodError
- **现象（预判）**：开发环境编译通过，生产 Forge 启动时找不到方法/字段。
- **根因**：Forge 生产环境使用 SRG 名；必须用 RAT `--reverse --map srg_to_official.tsrg` 重映射。
- **修复**：构建流水线固定为 javac(官方名) → 打包 dev jar → RAT 重映射 → 最终 jar。
- **防复发**：每次构建后检查 RAT 返回码；最终 jar 用 `javap` 抽查一个 MC 方法名是否为 `m_xxx_` 形式；部署前在专用服务器启动验证。
- **状态**：已规避（构建流程）。

### E03 客户端类被专用服务器加载
- **现象（预判）**：专用服务器启动报 `NoClassDefFoundError: net/minecraft/client/...`。
- **根因**：公共代码直接引用 `Screen`/`Minecraft`/`KeyMapping` 等客户端类。
- **修复**：客户端类全部放 `com.coc.client`；入口用 `DistExecutor.unsafeRunWhenOn(Dist.CLIENT, ...)` 反射加载 `ClientSetup`；客户端事件类标 `@Mod.EventBusSubscriber(value = Dist.CLIENT)`。
- **防复发**：专用服务器启动测试；`grep` 公共包不得出现 `net.minecraft.client` 导入（除 client 包内）。
- **状态**：待编码后验证。

### E04 事件 JSON 语法错误导致服务器启动崩溃
- **现象（预判）**：KP 手改事件 JSON 少逗号，服务器启动异常。
- **根因**：加载器未隔离单个文件错误。
- **修复**：逐文件 try/catch；记录文件名+错误；跳过坏文件；`/coc reload` 返回成功/失败数量。
- **防复发**：内置 JSON 全部用 `python -m json.tool` 校验；加载器必须有坏文件测试。
- **状态**：待编码后验证。

### E05 低 SAN 后处理误关其它模组效果
- **现象（预判）**：关闭 COC 特效后，原版蜘蛛/苦力怕/旁观者滤镜也消失。
- **根因**：直接调用 `shutdownEffect()` 未判断当前效果归属。
- **修复**：加载后保存自己的 `PostChain` 引用；只在 `currentEffect() == 自己的引用` 时关闭；设置关闭立即卸载；定期检测被其它效果覆盖时不强行抢回。
- **防复发**：手动测试：低 SAN 时被蜘蛛咬/旁观者模式切换后关闭 COC 特效，确认原版效果不被误关。
- **状态**：待编码后验证。

### E06 单人无作弊时 KP 命令被拒
- **现象（预判）**：单人存档未开作弊，`/coc event trigger` 提示无权限。
- **根因**：只按 OP 等级判定 KP。
- **修复**：`KpManager` 优先判定单人主机 UUID；其次 OP≥2；再次配置名单。
- **防复发**：单人无作弊、单人开作弊、专用服务器 OP/非 OP 四种场景测试。
- **状态**：待编码后验证。

### E07 事件超时/掉线导致 pending 卡死
- **现象（预判）**：玩家关掉事件界面/掉线，事件永久挂起。
- **根因**：pending 只存在内存且无超时清理。
- **修复**：每 20 tick 清理超时（默认 2400 tick）并按第一选项结算；玩家退出时移除 pending。
- **防复发**：超时测试 + 退出重进测试。
- **状态**：待编码后验证。

### E08 使用第三方 Sanity 模组会引入不必要依赖/冲突
- **调研结论**：Modrinth 上的 Sanity 类模组是"饥荒式理智"玩法，不含 COC 规则/角色卡/KP 事件，且版本/加载器不一。
- **决策**：不集成；自研规则层与本模组特效，避免依赖与版权/兼容风险。
- **状态**：已规避（设计决策）。

## 开发期自测发现并修复（2026-11-18）

### E09 小窗口（427×240 GUI）界面内容越界、按钮被挤出屏幕
- **现象**：窗口 854×480 + GUI Scale 2 时，创建/角色卡/掷骰/KP/设置界面出现列表被压扁、状态条超出面板、底部按钮重叠或消失。
- **根因**：界面按 854×480 GUI 坐标写死，未考虑 GUI Scale 2 只有 427×240 逻辑像素。
- **修复**：全部界面改为响应式布局；`height < 420 || width < 700` 使用紧凑布局（小字号、短间距、精简非核心控件、滚动列表）；否则普通布局。角色卡左侧状态区重新压缩，保证 SAN/HP/MP/幸运/状态在 182px 高度内完整显示。
- **防复发**：任何新界面必须至少在 427×240 与 854×480 两种 GUI 坐标下截图检查；禁止写死大于 400 的纵向间距。
- **状态**：已修复（截图验证）。

### E10 状态条数值黑字压在深色/彩色条上不可读
- **现象**：角色卡与 HUD 的 SAN/HP/MP 数值使用黑色文本，低 SAN 深色条或满血红色条上几乎看不清，且贴近条边缘被裁切。
- **根因**：数值颜色固定 `0xFF101010`，未考虑条填充色与未填充背景。
- **修复**：数值改为白色 + 阴影，右对齐到条内；角色卡条宽从 `leftW-26` 收紧到 `leftW-40`，避免超出面板。
- **防复发**：所有叠加在彩色背景上的文字使用白色/阴影或先画对比底板；截图检查深浅两种状态。
- **状态**：已修复（截图验证）。

### E11 KP 面板页签与分区标题重叠、第 4 个页签被教程 Toast 挡住
- **现象**：紧凑布局下“事件库/剧本库/在线玩家”标题与页签按钮重叠；居中页签的“工具”被右上角原版教程 Toast 覆盖。
- **根因**：分区标题画在 `contentY-11`，而页签占用了其上方空间；页签居中导致右侧落在 Toast 区域。
- **修复**：紧凑模式隐藏分区标题；页签改为左上角固定 `x=12`，四个页签不再进入右上 Toast 区域；工具页输入框加 `setHint` 说明用途。
- **防复发**：小窗口下不在页签区域附近画标题；顶部右侧 300px 视为 Toast 保留区。
- **状态**：已修复（截图验证）。

### E12 着色器加载时出现 InSize uniform 警告
- **现象**：`Shader color_convolve/wobble could not find uniform named InSize`。
- **根因**：原版 post 程序的 `InSize` 声明未参与实际计算被 GLSL 优化掉，PostChain 设置该 uniform 时打印警告；不是加载失败。
- **验证**：后处理成功生效，平均饱和度正常≈0.71 → 低 SAN≈0.20；关闭开关恢复≈0.54；无“后处理未生效”日志。
- **防复发**：不要把该警告当成 shader 失败；判断标准是 `GameRenderer.currentEffect()!=null` 与实际画面截图。
- **状态**：已确认无害，无需修复。

### E13 角色卡修改未标记世界存档为脏，可能丢 SAN/HP/技能变化
- **现象（代码审查）**：服务端直接修改 `CharacterSheet` 后只发包同步，没有 `SavedData.setDirty()`；仅事件冷却等偶尔触发保存。
- **根因**：角色卡对象由 `CocWorldData` 持有，但修改入口分散。
- **修复**：`CocNetwork.syncSheet()` 内统一调用 `CocData.get(server).putSheet(sheet)`，每次同步同时标记世界数据为脏，覆盖 SAN/HP/MP/技能/疯狂/线索/成长等所有路径。
- **防复发**：任何修改角色卡并同步的代码必须走 `syncSheet`；新增服务端修改入口检查是否落盘。
- **状态**：已修复。

### E14 测试用的自动脚本必须从交付 jar 移除
- **现象（风险）**：为验证界面与着色器临时加入 `ClientAutoTest`，由 `-Dcoc.autotest=true` 驱动；若遗留在交付 jar，正常玩家虽不会触发，但会留下无用测试代码。
- **根因**：测试钩子与正式代码同包编译。
- **修复**：测试完成后删除 `ClientAutoTest.java` 与 `ClientEvents` 中的调用，重新构建并部署；检查 jar 中无 `autotest` 类。
- **防复发**：测试专用代码放独立类并标记删除清单；交付前执行 `unzip -l | grep autotest` 检查。
- **状态**：已规避（最终 jar 已确认无该类）。

### E15 手动搭建 Forge 客户端测试环境时缺少 LWJGL 库
- **现象**：第一次手动启动客户端报 `NoClassDefFoundError: org/lwjgl/system/MemoryUtil`。
- **根因**：只复制了专用服务器的 legacy classpath（不含 LWJGL/客户端库）。
- **修复**：客户端测试 classpath 加入版本 JSON 中所有非 native 库 + `client-extra.jar`；`-Djava.library.path` 指向 1.20.1 natives。
- **防复发**：客户端测试与服务器测试的 classpath 分开；不要把 server 的 win_args 直接当 client 用。
- **状态**：已规避（测试环境问题，不影响交付 jar）。

### E16 技能加点后列表突然跳到选中项最底部
- **现象（用户反馈）**：在角色创建技能页点击“+5 兴趣/职业”后，列表会瞬间滚动，直到所选技能出现在最底部，观感很差。
- **根因**：`CocList.setItems()` 每次刷新都 `scroll=0`、`selected=-1`；随后恢复选中项时 `setSelectedIndex()` 调用 `ensureVisible()`，把列表滚到“刚好显示所选行”的位置，造成跳动。
- **修复**：新增 `setItemsKeepState()` 保留旧 scroll 与选中索引；`refreshSkillList()` 不再调用 `setSelectedIndex()`。角色卡刷新保存/恢复列表 scroll，KP 面板刷新也恢复三张列表的 scroll。
- **防复发**：任何“刷新同一列表数据”的场景禁用 `setItems()`；必须用 `setItemsKeepState()`。列表重建后必须恢复 scroll；不得在刷新路径里调用 `ensureVisible()`。
- **状态**：已修复（代码路径审查；待用户实机确认）。

### E17 剧本只有 6 幕、点自动结算 10 分钟就结束
- **现象（用户反馈）**：直接点“自动结算/下一幕”，六段结果文字很快播完，感觉没内容。
- **根因**：剧本事件只是“场景骨架”，每幕 2～3 个选项；自动结算跳过玩家讨论、调查、扮演。原剧本幕数也偏少。
- **修复**：
  1. 扩为 12 幕（新增井、告解、墓地、石台、仪式、黎明）并新增 5 个支线。
  2. KP 面板新增“幕”页，显示每幕概要与触发时机；可按玩家行动直接触发对应幕。
  3. 事件页按主线/支线/随机分类筛选。
  4. 文档明确：不要用“自动结算”代替玩家选择；每幕应 10～20 分钟。
- **防复发**：新增剧本至少 8～12 幕；每幕必须有“概要/触发时机/失败后果”；文档必须写“自动结算仅用于卡住时快进”。
- **状态**：已修复（v1.2.0）。

### E18 KP 面板事件无法看出属于哪一幕/何时触发
- **现象（用户反馈）**：事件列表混在一起，不知道玩家做了什么该点哪个事件。
- **根因**：事件只有标题/权重，没有分类与幕次元数据；剧本幕次与事件没有绑定展示。
- **修复**：`EventDef` 增加 category/act/triggerHint；事件页分类筛选并按幕排序；幕页显示触发提示与一键触发；文档附“玩家行动→触发事件”速查表。
- **防复发**：新增事件必须写 category；主线/支线必须写 act/triggerHint；新增剧本必须提供 acts 元数据。
- **状态**：已修复（v1.2.0）。

### E19 “使用官方模组”的概念与版权边界
- **背景（用户反馈）**：用户提出“使用官方模组”，可能指官方 TRPG 模组，也可能指官方 Minecraft mod。
- **调研结论**：不存在 Chaosium 官方授权/出品的 COC Minecraft 模组；现有 Minecraft 克苏鲁内容均为社区题材 mod（如 Cthulhu Fishing、AbyssalCraft），不含跑团规则。官方 COC 模组是 TRPG scenario（《鬼屋》《黑暗边缘》等）。
- **处理**：选择《鬼屋》的结构做中文原创改编；保留调查框架，文本全部重写，不复制官方正文；文档明确标注“结构参考，不含官方原文”。
- **防复发**：涉及“官方/授权”需求时先确认是 Minecraft mod 还是 TRPG scenario；官方 scenario 只能做结构改编/引用少量必要名词，不能整段复制；文档必须写清版权边界。
- **状态**：已处理（v1.3.0）。

### E20 连续“官方模组”需求要控制改编范围
- **背景**：用户连续要求《鬼屋》《无光信标》。逐个全文改编会变成大量版权敏感内容，也会让维护成本失控。
- **处理**：每个官方剧本只做**结构改编**（幕次/调查节点/检定/结局），正文原创；单剧本控制在 11 幕左右、5 个支线；文档明确“不含官方原文”。
- **防复发**：新增官方剧本改编时先写“结构映射表”，再写原创正文；不要复制官方 NPC 台词/段落；单剧本不超过 12 幕，避免内容膨胀。
- **状态**：已处理（v1.4.0）。

### E21 多剧本事件列表无法区分来源
- **现象（代码审查/预判）**：加入 3 个剧本后，事件页只显示 `[主线 1幕]`，不同剧本的同幕事件混在一起；标签加入完整剧本名又会挤掉标题。
- **修复**：事件增加 `scenarioTitle`；列表使用短名（低语/鬼屋/无光），排序按 分类→剧本→幕次；右侧显示完整标题。
- **防复发**：新增剧本必须在 `applyScenarioMetadata` 标注 `scenarioTitle`；事件列表标签使用短名，完整名称放详情区。
- **状态**：已修复（v1.4.1）。

### E22 删除角色是高危操作，必须二次确认
- **风险**：角色卡包含 SAN、技能、线索、疯狂状态，误删不可恢复。
- **处理**：命令分两步（先提示、再 `confirm`）；KP 面板按钮打开二次确认界面；删除前建议备份世界。
- **防复发**：所有不可逆的 KP 操作（删角色、清空线索、重置剧本）都必须二次确认，不能用单击直接执行。
- **状态**：已落实（v1.4.2）。

### E23 事件卡/自动结算把跑团变成了“点按钮”
- **现象（用户反馈）**：v1.4.2 的剧本每到一幕给所有玩家发事件卡，玩家只能点预设选项；KP 不能自由模拟，玩家也不能自由行动，自由度太低。
- **根因**：把“剧本内容”做成了“自动事件流程”；服务端主动发卡、自动检定、自动结算，KP 只剩推进按钮。
- **修复（v2.0.0）**：
  1. 剧本推进改为只发“幕布”（标题+介绍），无选项；
  2. 事件卡不再由剧本触发；玩家不再收到选项；
  3. KP 用剧情书看每幕走向/支线触发，口述选项与后果；
  4. 掷骰改为 KP 专属公开掷骰；道具/状态由 KP 工具处理。
- **防复发**：剧本团不要用自动选项流程；系统只提供“信息/工具”，决定权留给 KP 与玩家。新增剧本内容应进剧情书，不要做成玩家事件卡。
- **状态**：已修复（v2.0.0）。

### E24 小窗口下剧情书/道具/背景文字与按钮重叠
- **现象**：427×240 GUI 下，KP 剧情书页的说明文字被“主线剧情”按钮压住；道具页“道具目标值”标签压在“使用选中道具”按钮下；支线页底部说明压住列表；背景页最后一行被滚动提示/按钮截断。
- **根因**：新增界面按 854×480 估算 y 坐标，未按紧凑模式重新排版；文本区与按钮区没有预留滚动提示高度。
- **修复**：
  1. 剧情书页按钮整体下移到说明文字下方；
  2. 道具页把“目标”标签与输入框放到同一行，避免与上方按钮重叠；
  3. 删除支线页底部说明，避免压住列表；
  4. 背景页为滚动提示/按钮预留 76px；
  5. 剧情书左列表紧凑模式只显示标题，右详情加 4px 顶部内边距。
- **防复发**：任何新增 KP 页必须在 427×240 下截图；文本区、按钮区、滚动提示区三者分别计算，不得共用 y 区间。
- **状态**：已修复（截图 19~32）。

### E25 KP 在小窗口看角色卡看不到背景
- **现象（用户反馈）**：点击玩家角色卡时，KP 看不到角色背景；普通窗口有，小窗口没有。
- **根因**：`CharacterSheetScreen` 只在 `!compact` 时绘制背景，且没有独立入口；紧凑模式直接跳过。
- **修复**：角色卡底部新增“背景”按钮，打开独立 `BackstoryScreen`；六项背景+备注完整显示，支持滚轮，小窗口可用。玩家与 KP 都能打开。
- **防复发**：重要信息不要只放在“非紧凑模式才显示”的分支里；提供独立入口/页面。
- **状态**：已修复（截图 27/32）。

### E26 公开掷骰/道具检定只给 KP 或目标看，其他人看不到
- **风险**：旧 `CheckService.sendResult` 只发给掷骰者；KP 代掷时目标和其他玩家看不到，违背“骰子效果公开”。
- **修复**：新增 `broadcastPublic`：KP 技能掷骰、任意骰、道具使用检定均向所有在线玩家发送 `S2CRollResult` 与聊天摘要；目标玩家仍收到角色卡同步。
- **防复发**：任何 KP 代掷/公开检定路径必须走 `broadcastPublic`，不能走单发 `sendResult`。
- **状态**：已落实（实测聊天 50/50、59/45 均公开）。

### E27 版本升级后旧客户端/旧 jar 仍可连入，协议 ID 错位风险
- **风险**：v2.0.0 新增 4 个包 ID，但协议版本仍是 `1`；旧 1.4.2 客户端连入会按旧 ID 解析新包，可能断线/错乱。
- **修复**：`CocNetwork.PROTOCOL` 升为 `2`；客户端/服务端必须同为 2.0.0；`mods.toml` 与构建脚本版本同步为 2.0.0。
- **防复发**：新增/删除网络包必须升协议版本；部署时删除旧 `coc-*.jar`。
- **状态**：已修复。

### E28 玩家导入 JSON 如果直接复用事件格式，会带 effects/生成物/命令风险
- **风险**：直接把内部 EventDef JSON 开放给玩家上传，会允许 `spawn`、`item`、`effect` 等效果，甚至未来扩展命令效果；玩家可借此影响世界。
- **处理**：另定 `coc-scenario-v1` 简化格式，只接受文本、技能 id、难度、成功/失败/结果文字；不解析/不写入 effects、item、spawn、command。
- **防复发**：玩家可写内容与 KP 内部事件格式分离；新增导入字段前先确认不会执行服务端动作。
- **状态**：已落实。

### E29 导入剧本 id/文件名可能覆盖内置剧本或路径穿越
- **风险**：玩家自定义 id 若含 `../`、大写、斜杠，可能覆盖文件或写到目录外；与内置 id 重名会污染内容。
- **处理**：id 正则 `^[a-z][a-z0-9_]{2,31}$`；先检查 `EventRegistry.scenario(id)` 与目标文件是否存在；事件 id 由 `import_<id>_...` 生成；文件写入固定 config/coc 子目录。
- **防复发**：所有玩家可控文件名必须先过白名单正则 + 存在性检查；禁止直接使用原始输入拼路径。
- **状态**：已落实。

### E30 导入界面必须选 JSON 文件，而不是只支持剪贴板
- **现象（用户反馈）**：第一版用“复制 JSON 到剪贴板 → 从剪贴板导入”，用户明确要求“导入 Json 是 Json 文件，别用剪切板”。
- **根因**：为规避 Minecraft 文件选择器的跨平台问题，选择了剪贴板；但这不符合实际使用习惯。
- **修复**：改用 AWT `FileDialog` 文件选择器，在独立线程打开/读取，`Minecraft.execute` 回主线程发送；限制 `.json`、64KB；另提供“生成示例文件”到 `config/coc/example_scenario.json`。
- **防复发**：涉及“导入文件”的需求不要用剪贴板替代；系统对话框必须在后台线程，不能阻塞渲染线程；headless 环境要给出明确提示。
- **状态**：已修复。

### E31 工具页标题与输入框压在同一个 y 区间
- **现象（用户反馈）**：KP 面板“工具”页，发放线索/广播的标题、输入框、按钮文字错位重叠。
- **根因**：标题直接画在 `cy + 2` / `cy + 36`，而输入框从 `cy` 开始、按钮从 `cy + 22` 开始，三个层没有分层。
- **修复**：标题、输入框、按钮、广播区各自分配独立 y；输入框下移；数据警告下移；剧情书页按钮也下移。
- **防复发**：新增页必须按“标题行 → 输入行 → 按钮行 → 状态行”分层；交付前在 427×240 截图检查。
- **状态**：已修复（截图 37）。

### E32 道具技能/目标必须由服务端规则决定
- **风险**：如果只让客户端传目标值，客户端可伪造“必成功”；道具规则也无法统一。
- **修复**：`ItemLibrary` 服务端持久化 `id/skill/target`；`ItemService.use` 优先读取服务端规则，规则不存在才使用页面临时目标；客户端只负责显示/编辑。
- **防复发**：涉及判定目标的配置必须在服务端校验/落地，不能只信客户端输入。
- **状态**：已落实。

### E33 导入线索如果复用 effects/handout 效果会误执行
- **风险**：导入格式的“线索”若直接映射为事件 `handout` 效果，未来可能被自动结算路径执行，或给玩家错误发线索。
- **处理**：导入的 clue 只写入 `Outcome.handout` 文本，作为剧情书展示内容；不自动发给玩家，不执行 effects；要发给玩家仍用工具页手书。
- **防复发**：导入内容只作为 KP 参考文本；自动发线索必须走明确的手书操作。
- **状态**：已落实。

### E34 自动包裹 UI 字符串时误改了 JSON 示例文本块
- **现象（自查）**：为英文 UI 批量包裹中文字符串时，`ImportScenarioScreen` 的 Java 文本块 `SAMPLE` 里也出现了 `CocLang.tr(...)`，生成示例会变成非法 JSON。
- **根因**：正则按引号匹配，没有区分 Java 字符串和 text block 内容。
- **修复**：恢复 `SAMPLE` 为纯英文合法 JSON，并用 `json.loads` 校验；后续只对屏幕代码的字符串调用包裹，文本块单独处理。
- **防复发**：批量替换前排除 text block；示例 JSON 必须在构建前程序化解析验证。
- **状态**：已修复。

### E35 英文页签/按钮宽度不足
- **现象**：英文 `Player / Roll dice / Items / Story Book / Tools` 在 427×240 下页签互相压住；剧情书长标签被右边界截断。
- **修复**：页签英文缩短为 `Player / Roll / Items / Book / Tools`，紧凑宽度 48→52；剧情书长说明改为 `addWrapped`，`Possible Paths` 等标签缩短。
- **防复发**：英文 UI 必须单独做 427×240 截图；按钮/页签按英文长度重新分配宽度，不能沿用中文宽度假设。
- **状态**：已修复（截图 43~49）。

### E36 角色卡英文状态行被底部裁切
