## 一、用户指定的四条工作规则

### 规则 1：先分模块，模块必须可扩充
- 开工前先在 `01-模块与扩展设计.md` 写清模块边界、输入输出、扩展点。
- 不允许把所有逻辑堆进一个类；新玩法优先以"新增 JSON 数据 / 新增效果类型 / 新增面板"的方式接入。
- 每次新增功能必须回答三个问题：
  1. 它属于哪个模块？
  2. 它的扩展点是什么（数据？网络包？UI 页签？注册表？）
  3. 以后加同类内容是否需要改核心代码？

### 规则 2：动手前先上网找现成的
- 每个任务开始前先检索：CurseForge / Modrinth / mcmod.cn / GitHub / MinecraftForge 文档。

- 不确定：先下载/阅读源码或文档，再决定是否复用。
- 结果写入 `02-调研与复用记录.md`，包括：搜了什么、结论、复用了什么、为什么不用。

### 规则 3：完成一项任务后必须总结
- 每完成一个模块/可交付物，在 `03-完成记录.md` 追加：
  - 日期、版本、完成内容、涉及文件、验证方式、已知限制。
- 不允许"做完了但没记录"。

### 规则 4：收到错误反馈后先复盘，再建错误集
- 第一步：遍历 `03-完成记录.md` 中与本次错误相关的所有改动。
- 第二步：在 `04-错误反馈集.md` 新增条目（编号、现象、根因、修复、防复发检查项）。
- 第三步：把防复发检查项补进本表"开工检查清单"。
- 同一类错误不允许出现第二次。

## 二、项目目标（验收口径）

在 1.20.1 Forge 客户端中复刻《克苏鲁的呼唤》跑团体验：

1. **角色卡**：九项属性、衍生属性（HP/MP/SAN/幸运/移动/伤害加成/体格）、完整核心技能、职业与技能点分配、年龄修正、背景条目。
2. **掷骰**：d100 检定、奖惩骰、常规/困难/极难、大成功/大失败、孤注一掷、花费幸运、对抗检定、常规骰子表达式。
3. **完整 COC 核心规则**：SAN 检定与损失、临时性疯狂、不定期疯狂、恐惧症/狂躁症、克苏鲁神话与最大 SAN、技能成长检定、信用评级、伤害加成表。
4. **KP 主导的检定与道具**：只有 KP 能掷骰；KP 可为玩家公开掷技能/任意骰；道具发放、取走与使用检定；剧情书（主线/支线）与幕布式分幕。
5. **剧本（模组）**：KP 开始/推进/结束剧本；每一幕只给玩家发“标题+介绍”幕布，不自动发选项；KP 用剧情书口述走向。
6. **低 SAN 屏幕特效**：去饱和 + 画面扭曲（复用原版 post shader 程序，自建 JSON）、镜头晃动、边缘暗角、低语、心跳；**设置界面可一键关闭**。
7. **多人/单人**：服务端权威存档（SavedData）；单人主机/OP 为 KP；多人玩家各自角色卡；网络同步。
8. **玩家剧本导入**：玩家可选择 `coc-scenario-v1` JSON 文件，经服务端校验后写入 config/coc，剧情书自动出现新剧本；只接受文本/技能/结果/线索，不执行 effects/命令。
9. **KP 道具库/规则**：按物品 ID 加入道具列表，并为每件物品配置技能 ID + 目标点数（1~100）；服务端持久化并优先使用规则；剧情书每个选项标注成功/失败/直接线索或“无线索”。
10. **中英双语**：同一 jar 跟随 Minecraft 语言；客户端语言为 English 显示英文，简体中文显示中文；英文资源 `coc_en.json`，英文说明 `18-English-Guide.md`。

## 六、错误反馈处理模板（规则 4）

收到反馈后按顺序执行：

1. **复现**：记录现象、日志、发生场景（单人/多人、是否装 voicechat、是否低 SAN）。
2. **回溯**：在 `03-完成记录.md` 中找出相关模块最近 3 次改动，逐条核对。
3. **定位**：区分"规则实现错误 / 数据错误 / 网络同步错误 / UI 错误 / 环境问题"。
4. **修复**：最小改动修复，不做无关重构。
5. **写错误集**：在 `04-错误反馈集.md` 追加 E 编号条目，必须包含"防复发检查项"。
6. **回归**：重新编译 + 服务器启动 + 相关命令/界面自测。
7. **总结**：在 `03` 中写本次修复记录和版本号。
